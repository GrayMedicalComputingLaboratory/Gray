Gray API Reference

Gray Medical Computing Laboratory 的可复用训练研究框架 API。本文档对应当前 main 分支，说明输入、输出、异常和典型调用方式。

目录 安装与约定 配置与 CLI Experiment Callbacks Inference Preprocess Report Utils TTA DICOM / SimpleITK 边界

安装与约定

Gray 不包含项目专用模型、数据集和训练循环。项目通过 entrypoint 接入 Gray。

python -m pip install --upgrade "git+ssh://git@github.com/GrayMedicalComputingLaboratory/Gray.git@main"
每个实验只维护一个 YAML；YAML 文件名就是 experiment_id。生成的 trial 配置只是运行快照，不是第二份人工配置。

类型速查 / Type guide

标记含义典型值
PathLike字符串或 pathlib.Path 文件路径。"configs/exp_00.yaml"
Sequence[T]列表、元组或其他可迭代序列；除非特别说明，不接受空序列。["BCC", "Non-BCC"]
ArrayLikeNumPy 数组或可转换为数组的一维/二维数值序列。np.ndarray、list[float]
torch.TensorPyTorch 张量；TTA 保留 dtype、device 和梯度语义。[C,H,W] 或 [C,D,H,W]
sitk.ImageSimpleITK 图像对象，携带 spacing、origin、direction 和 metadata。DICOM volume

配置与 CLI

gray.core.config.load_config

load_config(path, overrides=()) -> tuple[dict, Path]

输入path：单个 YAML 路径；overrides：Hydra 风格的 key=value 列表。
输出解析后的普通字典和绝对配置路径；自动加入 experiment_id、_config_dir。
限制不允许 defaults、配置组或自动切换工作目录。
python -m gray.cli train --config configs/exp_00.yaml
python -m gray.cli train --config configs/exp_00.yaml --override train.lr=0.00003

项目 entrypoint 需返回字典，Gray 将其写入对应 stage 的 summary.json。

gray.core.config.resolve_path

resolve_path(config, value) -> Path

Parametersconfig 必须包含 _config_dir；相对路径从 YAML 所在目录解析，绝不依赖当前工作目录。
Returns绝对路径；传入绝对路径时保持其语义。

gray.core.config.artifact_dir

artifact_dir(config, stage, create=False) -> Path

Parametersstage 只能是相对单级目录名，不能为空、绝对路径或包含 ..；create=True 时创建目录。
Returnsoutput_root / experiment_id / stage。
Raises非法 stage 时抛出 ValueError。

gray.core.device.resolve_device

resolve_device(value: str | int) -> str

Accepted"cpu"、"cuda"、"cuda:N" 或非负 GPU 索引。
Returns规范化设备名，例如 cuda:0。
Raises设备格式错误抛出 ValueError；请求的 CUDA 不存在抛出 RuntimeError，不会静默回退 CPU。

gray.core.provenance.sha256 / model_manifest

sha256(path: Path) -> str
model_manifest(config, checkpoint: Path) -> dict

前者以流式方式计算文件哈希；后者保留扁平模型身份清单，记录实验、模型版本、数据版本、标签 schema、随机种子、fold、配置哈希、Git commit 和 checkpoint 哈希。

Experiment

统一管理 Experiment、Dataset、Git Code、Config、Training、Model 与 Evaluation 的可追溯关系。

gray.experiment.Experiment

Experiment(config, *, project_name=None, task_name=None, tags=None, output_uri=None, auto_connect_frameworks=True)

初始化创建新的 ClearML training Task，以 experiment_id 作为默认 Task Name，并将 ClearML Task ID 暴露为 run_id。
配置project_name、tags、output_uri 可显式传入或读取 config.tracking；连接到 ClearML 前自动移除内部字段并遮蔽凭据。
日志get_logger(name) 返回统一 logger：终端显示 Rich 颜色、写入本地 run.log、同步纯文本到 ClearML；metric(..., iteration=...) 同时生成 ClearML 标量曲线。
完成complete(checkpoint, evaluation=...) 生成 experiment_manifest.json，上传清单和 checkpoint，打印谱系并关闭 Task。
失败fail(reason) 在 ClearML 标记失败；作为上下文管理器使用时，未捕获异常会自动标记失败。
原生 SDKexperiment.task 仍返回 ClearML Task，用于 Gray 没有封装的曲线、图片和表格接口。

gray.experiment.experiment_manifest

experiment_manifest(config, checkpoint, *, evaluation=None, run_id=None) -> dict

关系显式建立 Experiment → Dataset / Git Code / Config → Training → Model → Evaluation 谱系。
Run ID可传 ClearML Task ID；不传时读取 config.run_id，与作为实验方案名的 experiment_id 分离。
身份保存数据版本、Git commit、配置版本及 SHA-256、checkpoint SHA-256、模型版本、训练 seed/fold 和评估结果。
输出带 schema_version 的 JSON 可序列化字典，可保存为文件或上传实验追踪系统。

gray.experiment.experiment_report

experiment_report(manifest, *, console=None) -> None

以 Rich 树和身份表显示 Experiment、输入版本、训练 Run、模型和评估状态。

from gray.experiment import Experiment

experiment = Experiment(config)
logger = experiment.get_logger("train")

logger.info("开始训练")
logger.metric("validation_auc", 0.93, iteration=10)
logger.success("训练完成")
manifest = experiment.complete(
    checkpoint,
    evaluation={"status": "passed", "roc_auc": 0.93},
)

Callbacks

训练流程中的状态型回调。回调只维护自身状态，不负责模型或 checkpoint 文件写入。

gray.callbacks.EarlyStopping

EarlyStopping(patience=5, mode="min", min_delta=0.0)

输入patience：允许连续不提升的步数；mode："min" 或 "max"；min_delta：最小有效提升幅度。
调用每次验证后调用 step(metric)；返回 True 时停止训练。reset() 可重新开始一轮监控。
状态state_dict() 返回可序列化状态；load_state_dict(state) 支持断点恢复。
异常参数不合法或指标不是有限数值时抛出 TypeError / ValueError。
from gray.callbacks import EarlyStopping

early_stopping = EarlyStopping(patience=5, mode="min")
for epoch in range(epochs):
    validation_loss = validate(...)
    if early_stopping.step(validation_loss):
        break

Inference

推理结果的通用后处理；不负责模型加载或前向计算。

gray.inference.Ensemble

Ensemble(*probabilities, method="mean", weights=None) -> np.ndarray

输入每个模型概率作为一个独立位置参数。二分类形状为 [n_samples]，多分类为 [n_samples, n_classes]；单模型直接传一个数组。
方法method="mean" 使用等权平均；method="weighted" 必须传入非负、有限且数量与模型一致的 weights。
输出与单个模型输出形状相同的 numpy.ndarray 概率。
限制只接收范围为 [0, 1] 的概率，不接收 logits；多分类每行概率和必须为 1。
from gray.inference import Ensemble

probabilities = Ensemble(
    model_a_probabilities,
    model_b_probabilities,
    method="weighted",
    weights=[0.6, 0.4],
)

Preprocess

无状态的 NumPy 图像预处理操作。

gray.preprocess.remove_background

remove_background(image, *, background_colors=0, tolerance=0.0, spatial_axes=(-2, -1)) -> np.ndarray

输入数值 NumPy 兼容数组。默认裁剪最后两个 H/W 轴，适用于 H,W、C,H,W 和 B,C,H,W。
背景background_colors 可传一个或多个灰度值/颜色向量；tolerance 用于忽略颜色误差。
体数据三维体数据使用 spatial_axes=(0, 1, 2) 裁剪全部体素轴。
输出包含前景的最小边界框视图；全为背景输入保持原数组和原形状。
from gray.preprocess import remove_background

cropped_image = remove_background(image, background_colors=[0, 255], tolerance=4)
cropped_volume = remove_background(volume, background_colors=0, spatial_axes=(0, 1, 2))

Report

在训练开始时统一展示实际配置和运行环境，便于核对与复现。

gray.report.training_report

training_report(config, *, console=None) -> None

输入解析后的配置 mapping；可选传入已有的 Rich Console。
配置表嵌套字段展开为点分路径；密码、token、secret 和 access key 自动显示为 <redacted>。
环境表显示 Python、操作系统、架构、解释器以及 Gray、PyTorch、Hydra、NumPy、SimpleITK、ClearML 等版本；未安装的可选包明确标记。
行为只读取已安装包的元数据，不导入 PyTorch、SimpleITK 等重型库，也不写入文件。
from gray.report import training_report

training_report(config)

Utils

gray.utils.seed_everything

seed_everything(seed: int, deterministic: bool = True) -> None

固定可用的 Python、NumPy、PyTorch、CUDA 和 cuDNN 状态；deterministic=True 会关闭 cuDNN benchmark 并请求确定性算法。函数只为子进程导出 PYTHONHASHSEED；当前解释器的 hash seed 必须在启动 Python 前设置。

gray.utils.seed_worker

seed_worker(worker_id) -> None

用于 PyTorch DataLoader(worker_init_fn=...)，根据 worker seed 固定 Python 与 NumPy。

gray.utils.torch_generator

torch_generator(seed) -> torch.Generator

返回可传给 DataLoader(generator=...) 的 PyTorch Generator。

gray.utils.get_logger

get_logger(name: str, output_dir: Path, *, tracker=None) -> GrayLogger

输入str logger 名称；pathlib.Path 输出目录；可选 ClearML Logger-compatible tracker。
输出GrayLogger；写入 Rich console 和 output_dir/run.log，不向 root logger 传播。
语义方法success(message) 使用绿色粗体；metric(name, value, iteration=0, title="Metrics") 使用青色粗体；warning 为黄色，error 为红色粗体。
ClearML建议通过 Experiment.get_logger() 获取：所有文本同步到 ClearML，metric 还会上报标量曲线；网页保存纯文本，不保留终端颜色。
文件日志只写纯文本，不包含 Rich 颜色或样式标签。
from gray.utils import get_logger

logger = get_logger("train", output_dir)
logger.success("训练完成")
logger.metric("validation_auc", 0.921)
logger.warning("数据量不足")
logger.error("checkpoint 保存失败")

clinical_binary_metrics

clinical_binary_metrics(targets, predictions, probabilities, positive_label=None, n_bins=10, n_bootstrap=2000, confidence=0.95, seed=42, thresholds=None) -> dict

组合 Sensitivity、Specificity、PPV、NPV、ROC-AUC、PR-AUC、ECE、Brier、bootstrap CI 和阈值报告。

目标与预测必须同时包含两个类别；单类 fold 使用通用指标。

clinical_binary_metrics 参数

参数支持类型要求与默认值
targets / predictionsSequence[Any]等长，且结果中必须能观测到正、负两个类别。
probabilitiesSequence[float] np.ndarray一维 P(positive_label)，长度与 targets 相同，值应在 [0,1]。
positive_labelAny | None显式建议传入；省略时由二分类标签集合推断。
n_binsint校准曲线分箱数，默认 10。
n_bootstrapintpercentile bootstrap 重采样次数，默认 2,000。
confidencefloat区间置信度，默认 0.95。
thresholdsSequence[float] | None待评估阈值；省略时使用内置网格。

clinical_binary_metrics 返回结构

Prevalencepositive_label、negative_label、samples、positive_prevalence。
Point estimatesaccuracy、sensitivity、specificity、ppv、npv、roc_auc、pr_auc。
Uncertaintyconfidence_intervals 对上述主要指标提供 percentile bootstrap 的 estimate / lower / upper / valid_bootstrap。
Calibrationcalibration.points 是绘图数据，另含 ECE 与 Brier score。
Thresholdsthreshold_report 逐阈值提供 Sensitivity、Specificity、PPV、NPV、F1 和 Youden J。

DICOM / SimpleITK

当前只使用 SimpleITK；不处理患者 metadata、Series 发现或 Series 选择。

函数输入输出源码
read_series项目已排序的 DICOM 路径列表sitk.ImageSource ↗
get_spacingsitk.Image正浮点 spacing 元组Source ↗
apply_rescalesitk.Image应用 Slope/Intercept 后的 ImageSource ↗
apply_window_levelImage、window_width、window_center映射到指定输出范围的 ImageSource ↗
apply_monochromeImage、MONOCHROME1/2?极性统一后的 ImageSource ↗
resample_volumeImage、target_spacing、interpolator重采样后的 Image；nearest 保持输入 pixel type，linear/bspline 为 float32Source ↗

DICOM 函数契约

函数支持输入输出与约束
read_seriesSequence[str | Path]，已经选择且排序的 DICOM 文件。sitk.Image；空序列抛出 ValueError，缺失文件抛出 FileNotFoundError。
get_spacingsitk.Imagetuple[float, ...]；所有 spacing 必须为正。
apply_rescalesitk.Imagesitk.Image float32；读取 DICOM slope/intercept metadata。
apply_monochromesitk.Image；可选 str | None interpretation。sitk.Image；只接受 MONOCHROME1 / MONOCHROME2。
apply_window_levelsitk.Image，float width、center、output_min、output_max。sitk.Image float32；width 必须 > 0，output_max 必须 > output_min。
resample_volumesitk.Image，Sequence[float] target_spacing，str interpolator。sitk.Image；仅 nearest、linear、bspline。
mask/label 使用 interpolator="nearest"；如果上游已经完成 rescale，不要重复调用 apply_rescale。nearest 保持输入 pixel type；linear/bspline 输出 float32，避免整数强制舍入插值结果。

推荐处理顺序

image = read_series(ordered_paths)
image = apply_rescale(image)              # stored -> physical units
image = apply_monochrome(image)           # MONOCHROME1 -> 2
image = apply_window_level(image, 400, 40)
image = resample_volume(image, (1.0, 1.0, 1.0))
read_series要求调用方已经完成 Series 选择和文件排序；空列表或缺失文件会抛出异常。
apply_rescale从 tags 0028|1053 / 0028|1052 读取 slope/intercept，slope 为 0 时拒绝处理。
apply_window_levellower=center-width/2、upper=center+width/2，再映射到 [output_min, output_max]。
